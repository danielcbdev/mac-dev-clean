# Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Establish agent guidance, honest Git history, a launchable native app, isolated modules and CI.

**Architecture:** A native Xcode app imports six targets in one local Swift package. Domain contains values and ports; app composition owns platform lifecycle.

**Tech Stack:** Swift 6, SwiftUI, XCTest, Xcode, Swift Package Manager, GitHub Actions.

**Spec:** [Approved specification](../specs/2026-09-21-macdevclean-design.md); [contracts](../specs/2026-09-21-interface-contracts.md).

## Global Constraints

- Product: MacDevClean; desktop application from the first runnable milestone.
- Swift 6 language mode; deployment target macOS 14; Xcode 16 or newer, with the exact tested Xcode build recorded.
- UI: English and Brazilian Portuguese; source, commits, technical documentation: English.
- SwiftUI, Observation, structured Swift Concurrency, Foundation, SwiftData and XCTest.
- No production runtime dependencies outside Apple frameworks; any build tooling dependency requires an ADR.
- No sandbox, privileged helper, administrator prompt, telemetry, server, scheduled deletion or background agent.
- Filesystem cleanup is Trash-only; no permanent filesystem deletion or empty-Trash command.
- Docker writes require a confirmed immutable selection, local endpoint verification and typed allowlisted commands.
- Tests operate on owned synthetic fixtures and fake destructive adapters; never on user caches, real Trash or existing Docker resources.
- Follow the approved spec plus the documented technical clarifications in docs/superpowers/specs/2026-09-21-implementation-clarifications.md.
- Do not publish, create remote repositories or upload artifacts without explicit authorization; local branches, commits and merges are authorized.

## Review Focus

- Opening from Finder must not depend on a terminal PATH: launch test in Task 2.
- Test fixtures must reject traversal paths: FixtureTree negative test in Task 2.
- A missing required toolchain must fail CI clearly: explicit selection in Task 3.
- Automatic scanning must stay off on first run: DefaultsTests in Task 2.
- Release compilation must not rely on DEBUG fixture types: Release build in Tasks 2–3.

```swift
import XCTest
import Domain
final class DefaultsTests: XCTestCase {
    func testNoAutomaticScanOrDeletion() {
        let preferences = AppPreferences()
        XCTAssertFalse(preferences.scanOnLaunch)
        XCTAssertEqual(preferences.largeFileThreshold, 1_000_000_000)
        XCTAssertEqual(preferences.language, .system)
        XCTAssertEqual(preferences.retention, .forever)
    }
}
```

### Task 3: Reproducible verification and CI

**Files:** scripts/verify.sh, scripts/lint.sh, .swift-format, .github/workflows/ci.yml, docs/adr/0001-modular-native-app.md, docs/adr/0002-toolchain.md, docs/verification/01-foundation.md.

**Interfaces:** produces scripts/verify.sh (exit 0 only if all checks passed) and scripts/lint.sh. Consumes shared scheme and package tests.

- [ ] Create verify.sh with this command body and `#!/bin/bash`, `set -euo pipefail`:
```bash
swift test --package-path Packages/MacDevCleanCore
xcodebuild -workspace MacDevClean.xcworkspace -scheme MacDevClean -destination 'platform=macOS' -derivedDataPath .build/xcode test CODE_SIGNING_ALLOWED=NO
xcodebuild -workspace MacDevClean.xcworkspace -scheme MacDevClean -configuration Release -destination 'platform=macOS' -derivedDataPath .build/release build CODE_SIGNING_ALLOWED=NO
bash scripts/lint.sh
git diff --check
```
Resolve repository root from the script's location before running. lint.sh uses the tested toolchain's `swift-format lint --strict --recursive` against Swift source roots (or `xcrun swift-format` if bundled there); verify availability and record version. Format once, then lint read-only. Do not fetch an unpinned formatter during CI.
- [ ] Add CI for pull_request and push on main/develop. Use a tested available macOS runner and explicit Xcode selection, read-only contents permission, cancel-in-progress concurrency, 30-minute timeout. Checkout uses a verified immutable action SHA. Run bash scripts/verify.sh. Upload xcresult on failure without secrets. The exact runner/Xcode pair must exist in GitHub's current runner inventory; document it at implementation time, fail if requested toolchain absent.
- [ ] Verify gate failure: temporarily introduce a wrong AppPreferences default, run the focused test and observe red, restore with a normal edit, then run verify.sh and observe green. Do not commit the intentional defect.
- [ ] Add progress/evidence files and ADR explaining six targets rather than six separate packages, no server, no privileged helper, and no runtime third-party dependency. Then commit and perform plan 00 branch lifecycle.
