## Branch lifecycle

Only run commands after inspecting git status; never discard unrelated work. Names below use scanning as a concrete example. Substitute the exact branch in the active plan.
```bash
git switch develop
git switch -c feat/scanning-engine
# Run each task's red/green cycle and focused commit.
git diff --check
bash scripts/verify.sh
git diff develop...HEAD
git switch develop
git merge --no-ff feat/scanning-engine -m "merge: integrate scanning engine"
bash scripts/verify.sh
git status --short
```

Keep feature branches until release. Do not fabricate dates, authors, review approvals or green checks. Record actual command, exit status, toolchain, date and known omissions in docs/verification/<milestone>.md. Use checked task boxes and docs/progress.md to track current branch, last completed task, next step, blockers and test evidence.

Each task step is intended as a 2–5 minute action. Repeat a red/green cycle for each named case rather than implementing a whole milestone in one untested patch. Steps in the documents include representative executable tests plus the exact case matrix; instantiate the cases as table-driven tests. No skipped tests or empty assertions count as completion.

Review every full branch diff for requirement coverage, security policy, API consistency and accessibility. If using independent reviewers, record their actual findings and resolutions; ordinary self-review is still mandatory. Never imply an independent review happened when it did not.

## Verification commands

Plan 01 supplies scripts/verify.sh and scripts/lint.sh. Baseline:
```bash
swift test --package-path Packages/MacDevCleanCore
xcodebuild -workspace MacDevClean.xcworkspace -scheme MacDevClean -destination 'platform=macOS' -derivedDataPath .build/xcode test CODE_SIGNING_ALLOWED=NO
xcodebuild -workspace MacDevClean.xcworkspace -scheme MacDevClean -configuration Release -destination 'platform=macOS' -derivedDataPath .build/release build CODE_SIGNING_ALLOWED=NO
bash scripts/lint.sh
git diff --check
```

UI tests run in a logged-in macOS session with fake dependencies selected by a DEBUG-only launch argument. CI records unavailable UI test infrastructure as a missing gate, not PASS. Test Debug and Release compile paths so fixture switches cannot leak into a shipping binary.

## Resume and uncertainty

Inspect branch, status, last commits and docs/progress.md. Rerun only stale or affected checks; do not recreate branches or duplicate commits. If a plan's sample code needs an SDK correction, preserve its behavior, fix the contract consistently, add a regression test and record the reason in an ADR. No speculative architecture rewrite.

Resolve Xcode identity, signing team, remote owner, account credentials and public URLs only at release time. The agent can finish local app, tests and unsigned DMG without them. Stop only the dependent release operation; report exact remaining steps.

## Release lifecycle

After plan 09: create release/1.0.0 from develop. Fix only release issues there. Re-run all gates and manually exercise the packaged fixture build. Once all required release gates are satisfied, merge release/1.0.0 into main, tag v1.0.0, merge main into develop. Local tagging is authorized only when version criteria are met. Push/publish needs separate user authorization.

If signing or public installation is still pending, retain a release candidate branch/artifact and call it that. main must not advertise completed notarization or public availability without evidence.
