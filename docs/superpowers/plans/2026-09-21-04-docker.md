# Docker Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Inspect and clean local Docker resources with explicit data-loss risk and exact reviewed targets.

**Architecture:** A typed process port serves capability discovery, schema parsers and a constrained DockerClient adapter. The cleanup executor remains the authority for consent and history.

**Tech Stack:** Foundation Process, JSONDecoder, Swift actors, XCTest fixtures.

**Spec:** [Approved specification](../specs/2026-09-21-macdevclean-design.md); [technical clarifications](../specs/2026-09-21-implementation-clarifications.md); [contracts](../specs/2026-09-21-interface-contracts.md).

## Global Constraints

- Product: MacDevClean; desktop application from the first runnable milestone.
- Swift 6 language mode; deployment target macOS 14; Xcode 16 or newer, with the exact tested Xcode build recorded.
- UI: English and Brazilian Portuguese; source, commits, technical documentation: English.
- SwiftUI, Observation, structured Swift Concurrency, Foundation, SwiftData and XCTest.
- No production runtime dependencies outside Apple frameworks; any build tooling dependency requires an ADR.
- No sandbox, privileged helper, administrator prompt, telemetry, server, scheduled deletion or background agent.
- Filesystem cleanup is Trash-only; no permanent filesystem deletion or empty-Trash command.
- Docker writes require a confirmed immutable selection, local endpoint verification and typed allowlisted commands.
- Tests operate on owned synthetic fixtures and fake destructive adapters; never on user caches, real Trash or existing Docker resources.
- Follow the approved spec plus the documented technical clarifications in docs/superpowers/specs/2026-09-21-implementation-clarifications.md.
- Do not publish, create remote repositories or upload artifacts without explicit authorization; local branches, commits and merges are authorized.

## Review Focus

- A remote context accidentally active must never be cleaned: Task 1.
- Missing/changed JSON fields must fail closed, not imply eligibility: Task 2.
- A volume referenced by a stopped container is still in use: Task 2.
- A context/resource changing after review must prevent removal: Task 3.
- A timed-out write may already have happened and must not retry blindly: Task 3.

### Task 1: Bounded subprocess I/O and local capability

**Files:** Packages/MacDevCleanCore/Sources/Domain/ProcessTypes.swift, Sources/DockerIntegration/{LocalProcessRunner,DockerDiscovery}.swift, Sources/TestSupport/RecordingProcessRunner.swift, Tests/DockerIntegrationTests/{DiscoveryTests,ProcessRunnerTests}.swift (package-relative); docs/adr/0004-local-docker.md.

**Interfaces:** ProcessRunning returns both streams and exit status. DockerDiscovery.discover(executable:context:) async throws -> DockerCapability. Define DockerCapability with executable URL, contextName, endpoint URL, daemonID, builderName?, buildCacheSupported Bool and fingerprint String. Its digest includes endpoint, daemon ID and builder identity, never just a mutable context name.

- [ ] Write discovery tests with fake command output: missing executable, daemon offline, user-selected Unix socket context accepted, tcp/ssh rejected, builder on remote node rejected, context changed after scan rejected. Executable candidates: explicit user choice, /Applications/Docker.app/Contents/Resources/bin/docker, /usr/local/bin/docker, /opt/homebrew/bin/docker. Resolve installation symlink and show actual binary; do not search writable project directories or run a login shell.
```swift
func testRemoteEndpointIsRejected() throws {
    XCTAssertThrowsError(try DockerDiscovery.validateEndpoint("ssh://server")) {
        XCTAssertEqual($0 as? PolicyError, .outsideScope)
    }
}
```
Define static validateEndpoint(_ value: String) throws -> URL, accepting only Unix socket URLs after normalization/validation.
- [ ] Run DiscoveryTests red. Implement read-only discovery with explicit executable and --context. Inspect context JSON before daemon calls; ignore inherited DOCKER_HOST, DOCKER_CONTEXT and BUILDX_BUILDER. Allow only reviewed local Docker Desktop endpoints. Driver/plugin volumes and multi-node/remote builders are inspection-only.
- [ ] Build LocalProcessRunner with concurrent draining of stdout/stderr, 8 MiB output bound, 10-second discovery and 60-second write timeout. Define ProcessError enum cases timeout, outputLimit, launchFailure, cancelled. On cancel terminate the child and await exit; ensure pipes close and continuation resumes once. Never invoke /bin/sh or sudo. Add real non-destructive process tests using /usr/bin/printf, /bin/sleep and a Swift test helper emitting >pipe buffer to both streams.
```swift
let request = ProcessRequest(executable: URL(fileURLWithPath: "/usr/bin/printf"),
    arguments: ["%s", "$(touch should-not-exist)"], environment: [:],
    timeoutSeconds: 5, outputLimit: 1024)
let output = try await LocalProcessRunner().run(request)
XCTAssertEqual(String(decoding: output.stdout, as: UTF8.self), "$(touch should-not-exist)")
```
Do not execute the apparent shell expression; it is a literal argument. Add timeout/cancel/output-limit cases.
- [ ] Run DiscoveryTests and ProcessRunnerTests green. Commit:
```bash
git add Packages docs
git commit -m "feat: discover local Docker with bounded subprocess execution"
```

### Task 2: Machine-readable inventory and uncertainty

**Files:** Packages/MacDevCleanCore/Sources/DockerIntegration/{DockerDTOs,DockerParser,LocalDockerClient}.swift, Tests/DockerIntegrationTests/ParserTests.swift, Tests/DockerIntegrationTests/Fixtures/*.json (package-relative).

**Interfaces:** DockerParser.buildCache(_ data: Data) throws -> [BuildCacheDTO]; define DTO fields id String, size UInt64?, reclaimable Bool, shared Bool, mutable Bool. LocalDockerClient(discovery:runner:clock:) implements DockerClient. Inventory candidate IDs are generated per snapshot; provenance fingerprint binds each candidate.

- [ ] Write fixtures from documented schemas (sanitized captured output later replaces synthetic examples), with numeric Size encoded as a string:
```swift
func testBuildCacheSizeStringAndSharedStatus() throws {
    let data = Data(#"{"ID":"abc123","Size":"4096","Reclaimable":true,"Shared":true,"Mutable":false}"#.utf8)
    let row = try XCTUnwrap(DockerParser.buildCache(data).first)
    XCTAssertEqual(row.size, 4096)
    XCTAssertTrue(row.shared)
}
```
Test missing ID, malformed JSON, unknown fields, missing size -> nil, negative/overflow size -> nil + issue, missing reclaimable -> ineligible. Never treat missing boolean as safe true. Shared rows excluded from exact reclaimable sum.
- [ ] Run ParserTests red, then implement JSONDecoder DTO adapters with explicit coding keys and versioned fixture schema. Docker commands for reads:
```text
docker --context CONTEXT version --format {{json .}}
docker context inspect CONTEXT
docker --context CONTEXT info --format {{json .}}
docker --context CONTEXT container ls --all --no-trunc --format {{json .}}
docker --context CONTEXT container inspect --size ID
docker --context CONTEXT image ls --no-trunc --format {{json .}}
docker --context CONTEXT image inspect ID
docker --context CONTEXT volume ls --format {{json .}}
docker --context CONTEXT volume inspect NAME
docker --context CONTEXT buildx inspect BUILDER
docker --context CONTEXT buildx du --builder BUILDER --format=json
```
Each token is a separate Process argument, braces included literally. No Docker start, pull, run or builder bootstrap. Read-only capability probe determines whether Buildx supports JSON and precise id filtering; disable only that feature if unavailable.
- [ ] Compare images/volumes with mounts and image IDs of ALL containers, not just running containers. A stopped container is high risk due to writable data. Treat volume size as unknown unless authoritative local daemon data supplies it; do not mount volumes or read Docker.raw. Image sizes share layers and are estimates; use separate resource-kind totals and no exact “GB freed” promise.
- [ ] Merge DockerInventory with filesystem results in app composition later, registering snapshot evidence. Preserve unavailable/partial states. Run tests and commit:
```bash
git add Packages docs
git commit -m "feat: parse Docker inventory with explicit risk and unknown sizes"
```

### Task 3: Exact-target commands and write revalidation

**Files:** Packages/MacDevCleanCore/Sources/DockerIntegration/{DockerCommandFactory,LocalDockerClient}.swift, Tests/DockerIntegrationTests/CommandTests.swift (package-relative); docs/security/docker-policy.md, docs/verification/04-docker.md.

**Interfaces:** DockerCommandFactory.arguments(for:context:builder:) throws -> [String], where first parameter is DockerResource(kind:id:) with public init and DockerOperation kind. Factory only produces allowlisted removal arguments. LocalDockerClient.revalidate checks live context/daemon, existence, identity and in-use state before remove.

- [ ] Write exact argument assertions:
```swift
func testContainerRemovalCannotForceOrRemoveVolumes() throws {
    let resource = DockerResource(kind: .container, id: String(repeating: "a", count: 64))
    let args = try DockerCommandFactory.arguments(for: resource, context: "desktop-linux", builder: nil)
    XCTAssertEqual(args, ["--context", "desktop-linux", "container", "rm",
                         String(repeating: "a", count: 64)])
}
```
Test high-risk missing consent at Cleanup validator, malformed IDs starting "-", ID with shell punctuation rejected, changed context, running transition, newly attached volume, image referenced by stopped container and unknown Buildx capability. Test 2 selected resources results in exactly 2 bounded requests.
- [ ] Run CommandTests red. Implement:
```text
container: --context CONTEXT container rm FULL_ID
image:     --context CONTEXT image rm --no-prune FULL_ID
volume:    --context CONTEXT volume rm REVIEWED_NAME
cache:     --context CONTEXT buildx prune --builder BUILDER --filter id=RECORD_ID --filter inuse=false --force
```
Only the precise Buildx command uses --force, to suppress its prompt after app confirmation. No --all, broad system/builder/container/image/volume prune, image force, container force or --volumes. Use strict identifier validation: container 64 lowercase hex, image sha256: plus 64 lowercase hex, volume ASCII letter/digit followed by letters/digits/_.-, cache alphanumeric token as observed schema. Reject empty, option-like or control-character strings.
- [ ] Reinspect before every call; mark changed/missing resources skipped. Do not automatically delete a volume that becomes unused because an earlier selected container was removed: it was not eligible in the reviewed snapshot. Refuse multi-tag image operations if non-force removal cannot address the exact reviewed resource without unreviewed effects.
- [ ] Test timeout during write produces indeterminate state unless post-inspection confirms absence, never blindly retry. Add source link and exact capabilities to docker-policy.md. Run full verify.sh, commit, merge.
```bash
git add Packages docs
git commit -m "feat: constrain Docker cleanup to reviewed local resources"
```

## Exit gate

All Docker tests pass with no real daemon. Missing/remote Docker cannot disrupt filesystem features. Every irreversible action is exact-target, context-bound, revalidated, confirmed and journaled. Live Docker testing is opt-in with explicit authorization and disposable resources only.
