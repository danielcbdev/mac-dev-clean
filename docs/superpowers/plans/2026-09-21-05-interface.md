# Desktop Interface Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the complete native scan-to-review-to-results workflow using the approved visual reference.

**Architecture:** MainActor observable feature models consume injected services; NavigationSplitView coordinates destinations and preserves state.

**Tech Stack:** SwiftUI, Observation, AppKit, String Catalogs, XCTest UI automation.

**Spec:** [Approved specification](../specs/2026-09-21-macdevclean-design.md); [contracts](../specs/2026-09-21-interface-contracts.md); docs/references/macdevclean-ui-reference.png.

## Global Constraints

- Product: MacDevClean; desktop application from the first runnable milestone.
- Swift 6 language mode; deployment target macOS 14; Xcode 16 or newer, with the exact tested Xcode build recorded.
- UI: English and Brazilian Portuguese; source, commits, technical documentation: English.
- SwiftUI, Observation, structured Swift Concurrency, Foundation, SwiftData and XCTest.
- No production runtime dependencies outside Apple frameworks; any build tooling dependency requires an ADR.
- No sandbox, privileged helper, administrator prompt, telemetry, server, scheduled deletion or background agent.
- Filesystem cleanup is Trash-only; no permanent filesystem deletion or empty-Trash command.
- Docker writes require a confirmed immutable selection, local endpoint verification and typed allowlisted commands.
- Tests operate on owned synthetic fixtures and fake destructive adapters; never on user caches, real Trash or existing Docker resources.
- Follow the approved spec plus the documented technical clarifications in docs/superpowers/specs/2026-09-21-implementation-clarifications.md.
- Do not publish, create remote repositories or upload artifacts without explicit authorization; local branches, commits and merges are authorized.

## Review Focus

- A canceled old scan must not overwrite a newer result: Task 1.
- Filtering must not silently alter the selected cleanup scope: Task 2.
- Large translated text must not hide the primary action: Task 2 layout inspection and plan 08.
- Double-click confirmation must schedule only one cleanup: Task 3.
- Mixed Trash/Docker results must distinguish recoverability and bytes: Task 3.

### Task 1: Composition, first-run scope and scan state

**Files:** MacDevCleanApp/App/{MacDevCleanApp,AppDependencies,RootCoordinator,AppState,AppSafetyContextProvider,CompositeScanService,SessionRepositories}.swift; Features/Onboarding/{OnboardingView,RootSelectionModel}.swift, Features/Overview/ScanModel.swift, Platform/{NativeFolderPicker,NativeWorkspaceOpener}.swift, PreviewSupport/PreviewDependencies.swift, MacDevCleanAppTests/ScanModelTests.swift (app-relative); MacDevCleanUITests/OnboardingUITests.swift.

**Interfaces:** ScanModel and app ports from contracts. CompositeScanService(filesystem:docker:store:context:) implements ScanService, registers a combined snapshot under one ID. AppState tracks onboarding, idle, scanning, results, reviewing, cleaning, completed; revisiting a screen cannot start a second scan.

- [ ] Write UI test before first-run implementation:
```swift
func testNoScanStartsBeforeRootConsent() {
    let app = XCUIApplication()
    app.launchArguments = ["--ui-testing", "--scenario", "first-run"]
    app.launch()
    XCTAssertTrue(app.buttons["roots.choose"].waitForExistence(timeout: 5))
    XCTAssertFalse(app.progressIndicators["scan.progress"].exists)
    app.buttons["roots.choose"].click()
    app.buttons["roots.confirm"].click()
    XCTAssertTrue(app.buttons["scan.start"].waitForExistence(timeout: 5))

```
The injected FolderPicking fake returns a synthetic root; this is not an attempt to automate NSOpenPanel. Separately manually verify the actual native picker cancellation and multi-selection.
- [ ] Add ScanModel tests with ReplayScanService(events:) in test support: start emits incremental progress then snapshot; selectedIDs stays empty; canceled run cannot overwrite newer run; Docker unavailable emits issue while filesystem results survive; removed root clears affected selection. ReplayScanService implements ScanService with deterministic gated continuations, not time sleeps. Run app tests red.
- [ ] Implement composition: real filesystem/policy/catalog/registry + LocalDockerClient or unavailable adapter. Until plan 07, the runnable app may scan real approved roots but its cleanup UI remains in fixture demonstration mode; live side effects require the durable journal. Implement App/SessionRepositories.swift as actor-owned in-memory SettingsRepository and HistoryRepository for this intermediate demo. Do not import test-support implementations into production targets. NativeFolderPicker wraps NSOpenPanel on MainActor with canChooseDirectories and allowsMultipleSelection; roots only saved on confirmation. Feature models retain/cancel one Task and ignore events whose generation ID differs.
```swift
selectedIDs = []
let generation = UUID()
activeGeneration = generation
scanTask = Task { [weak self, scanner] in
    do {
        for try await event in scanner.scan(request) {
            guard !Task.isCancelled, self?.activeGeneration == generation else { break }
            self?.receive(event)
        }
    } catch is CancellationError {
        self?.finishCancellation(generation)
    } catch {
        self?.finishFailure(generation, code: "scan.failed")
    }
}
```
Define receive(_ event: ScanEvent), finishCancellation(_ generation: UUID), finishFailure(_ generation: UUID, code: String) as private ScanModel helpers. isScanning settles on all terminal paths. Cancel current work on model disposal and app termination where practical.
- [ ] In DEBUG-only composition, --ui-testing selects app-local preview adapters for fake files, fake Trash, fake Docker, in-memory persistence and fixture roots as one bundle. The Xcode app never imports the package TestSupport target; XCTest targets can import it. Release ignores/rejects these arguments and compiles preview adapters out. Until plan 07 wires the durable journal, Release cleanup actions display unavailable. Verify Release build.

A user can launch, authorize roots, scan, select, understand risk, confirm and see results. Automated flows use only fakes. No static mock data in production composition; no cleanup action before confirmation.
