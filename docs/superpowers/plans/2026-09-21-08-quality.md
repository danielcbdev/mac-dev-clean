# Localization Accessibility and Quality Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish the bilingual accessible UI and validate performance and privacy with reproducible evidence.

**Architecture:** Shared formatting and semantic controls keep features consistent; stress tests exercise real services through deterministic ports.

**Tech Stack:** String Catalogs, Foundation formatting, SwiftUI accessibility, XCTest/XCUITest, OSLog.

**Spec:** [Approved specification](../specs/2026-09-21-macdevclean-design.md); [contracts](../specs/2026-09-21-interface-contracts.md).

## Global Constraints

- Product: MacDevClean; desktop application from the first runnable milestone.
- Swift 6 language mode; deployment target macOS 14; Xcode 16 or newer, with the exact tested Xcode build recorded.
- UI: English and Brazilian Portuguese; source, commits, technical documentation: English.
- SwiftUI, Observation, structured Swift Concurrency, Foundation, SwiftData and XCTest.
- No production runtime dependencies outside Apple frameworks; any build tooling dependency requires an ADR.
- No sandbox, privileged helper, administrator prompt, telemetry, server, scheduled deletion or background agent.
- Filesystem cleanup is Trash-only; no permanent filesystem deletion or empty-Trash command.
- Docker writes require a confirmed immutable selection, local endpoint verification and typed allowlisted commands.
- Tests operate on owned synthetic fixtures and fake destructive adapters; never on user caches, real Trash or existing Docker resources.
- Follow the approved spec plus the documented technical clarifications in docs/superpowers/specs/2026-09-21-implementation-clarifications.md.
- Do not publish, create remote repositories or upload artifacts without explicit authorization; local branches, commits and merges are authorized.

## Review Focus

- Plural placeholders can mismatch across languages: Task 1.
- Unknown size must not display as zero: Task 1.
- Long pt-BR warnings and larger text must remain readable: Task 2.
- Reduced-motion settings must suppress progress decoration: Task 2.
- Huge trees and canceled scans must not keep consuming memory/I/O: Task 3.

### Task 3: Performance, privacy and regression gates

**Files:** Packages/MacDevCleanCore/Tests/ScanningTests/ScanPerformanceTests.swift, Sources/TestSupport/{SyntheticFileSystem,PerformanceHarness}.swift (package-relative); MacDevCleanApp/MacDevCleanAppTests/PrivacyExportTests.swift, scripts/{verify,check-policy}.sh, docs/testing/performance.md, docs/verification/08-quality.md.

**Interfaces:** ScanPerformanceTests uses generated metadata through FileSystemClient (100,000 entries) and a smaller real-file fixture (5,000 entries). Define SyntheticFileSystem(count: Int) in TestSupport to generate deterministic entries lazily. Cancellation and visited-read counts are observable; no allocation of huge file content.

- [ ] Write behavioral cancellation test with gate-controlled fake I/O, no sleep:
```swift
func testCancellationStopsReadingAdditionalBatches() async throws {
    let files = SyntheticFileSystem(count: 100_000)
    let run = try await PerformanceHarness.start(files: files)
    await files.waitForFirstBatch()
    run.task.cancel()
    await files.releaseBlockedBatch()
    await run.task.value
    let reads = await files.readCount()
    XCTAssertLessThanOrEqual(reads, SyntheticFileSystem.batchSize * 2)
}
```
Define PerformanceHarness.start(files:) using real DeveloperScanner and valid Node manifests in synthetic tree; returns struct PerformanceRun(task: Task<Void,Never>). Expose waitForFirstBatch(), releaseBlockedBatch(), readCount(), static batchSize=256 in SyntheticFileSystem. Do not assert wall-clock microbenchmarks in shared CI.
- [ ] Run red where cancellation currently over-reads; if already green, retain as regression and add the missing stress condition rather than intentionally breaking working code. Measure XCTest clock/memory metrics, record toolchain/CPU and file counts. Use dedicated manually triggered performance job to avoid 100k fixture generation on every test run.
- [ ] Run app while 100k metadata scan active: navigation/Cancel must respond; record p50/p95 sample UI response and cancellation latency, memory peak and throughput. Optimize only evidenced bottlenecks (batch events, autoreleasepool in enumeration, limit concurrency to 4 roots or fewer). Re-run affected performance tests after changes.
- [ ] Add scripts/check-policy.sh with ripgrep rules rejecting production cleanup shell commands, FileManager.removeItem within cleanup source, shell Process executables, hardcoded private home paths and telemetry SDK imports. Allow FixtureTree teardown explicitly; static check complements behavioral tests, not proves security. Add positive/negative test fixtures for checker rules.
- [ ] PrivacyExportTests feed fixture marker “private-customer-database” and original/Trash paths into outcomes; assert exported diagnostic contains only codes/counts/version. Offline smoke exercises all non-Docker screens. Run full verify.sh with localization and policy scripts included.
