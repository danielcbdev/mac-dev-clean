# Cleanup Safety Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn reviewed IDs into bounded, revalidated operations and auditable outcomes.

**Architecture:** Validation capabilities and execution stay in Cleanup; injected filesystem, Docker and journal ports isolate effects. Public constructors cannot mint authority.

**Tech Stack:** Swift 6 actors, Foundation Trash API, XCTest.

**Spec:** [Approved specification](../specs/2026-09-21-macdevclean-design.md); [contracts](../specs/2026-09-21-interface-contracts.md).

## Global Constraints

- Product: MacDevClean; desktop application from the first runnable milestone.
- Swift 6 language mode; deployment target macOS 14; Xcode 16 or newer, with the exact tested Xcode build recorded.
- UI: English and Brazilian Portuguese; source, commits, technical documentation: English.
- SwiftUI, Observation, structured Swift Concurrency, Foundation, SwiftData and XCTest.
- No production runtime dependencies outside Apple frameworks; any build tooling dependency requires an ADR.
- No sandbox, privileged helper, administrator prompt, telemetry, server, scheduled deletion or background agent.
- Filesystem cleanup is Trash-only; no permanent filesystem deletion or empty-Trash command.
- Docker writes require a confirmed immutable selection, local endpoint verification and typed allowlisted commands.
- Tests operate on owned synthetic fixtures and fake destructive adapters; never on user caches, real Trash or existing Docker resources.
- Follow the approved spec plus the documented technical clarifications in docs/superpowers/specs/2026-09-21-implementation-clarifications.md.
- Do not publish, create remote repositories or upload artifacts without explicit authorization; local branches, commits and merges are authorized.

## Review Focus

- A selected item replaced after scanning must be skipped: Task 2.
- An exclusion added while review is open must invalidate the plan: Task 1.
- Repeating a confirmation must not repeat a destructive effect: Task 2.
- Journal failure after a side effect must not trigger a retry: Task 3.
- Moving to Trash must not be reported as immediate freed disk space: Task 3.

### Task 2: Serial executor, revalidation and cancellation

**Files:** Packages/MacDevCleanCore/Sources/Cleanup/{CleanupExecutor,FileManagerTrashClient}.swift, Sources/TestSupport/{RecordingTrash,CleanupCollector}.swift, Tests/CleanupTests/ExecutionTests.swift (package-relative); docs/security/threat-model.md.

**Interfaces:** CleanupExecutor implements CleanupExecuting; FileManagerTrashClient implements TrashClient. Executor actor owns consumed plan IDs and active run. execute returns a stream via a nonisolated facade scheduling actor work, using onTermination cancellation. Execution services do not run on MainActor.

- [ ] Test time-of-check/time-of-use with fixture replacement:
```swift
func testReplacementAfterReviewIsNeverTrashed() async throws {
    let harness = try await CleanupHarness()
    let candidate = try await harness.candidate(file: "project/node_modules",
                                               rule: "node.modules", risk: .low)
    let selection = await harness.selection(for: [candidate.id],
                                            irreversible: false, highRisk: false)
    let plan = try await harness.validate(selection)
    try await harness.replaceWithDifferentIdentity(candidate.id)
    let result = await harness.execute(plan)
    XCTAssertEqual(result.records.first?.errorCode, PolicyError.changed.rawValue)
    let calls = await harness.trash.calls()
    XCTAssertTrue(calls.isEmpty)
}
```
Define replaceWithDifferentIdentity in harness by renaming the original inside the owned fixture, creating a distinct replacement, preserving both until fixture teardown; never unlink a user path.
- [ ] Test ancestor symlink replacement, expiry with MutableTestClock advancing 61 seconds, second execution of same token, one permission failure followed by a valid item, unavailable Trash, cancellation after first item. Add MutableTestClock to TestSupport as thread-safe clock with a lock and advance(seconds:); no unsafe Sendable state.
- [ ] Run ExecutionTests red, then implement the serial loop: consume token once, read live revision, begin journal, for each item check cancellation/identity/rule evidence/live exclusion and invoke the appropriate port. Recheck all ancestor symlinks, not only the leaf. The core real filesystem operation is:
```swift
var resultingURL: NSURL?
try fileManager.trashItem(at: url, resultingItemURL: &resultingURL)
guard let result = resultingURL as URL? else { throw PolicyError.unavailable }
return result
```
Run this inside the bounded utility I/O adapter. No fallback permanent deletion. Missing result URL after successful Trash is an indeterminate result, not permission to repeat the move; record that limitation explicitly.
- [ ] Every scheduled item gets a final status, including remaining canceled ones. A client cancel during a Docker write may leave its outcome indeterminate—post-inspect when possible. Do not claim rollback. Emit exactly one terminal summary. Re-run tests green.

### Task 3: Journal reliability and truthful outcome accounting

**Files:** Packages/MacDevCleanCore/Sources/TestSupport/InMemoryJournal.swift, Sources/Cleanup/CleanupExecutor.swift, Tests/CleanupTests/JournalTests.swift (package-relative); docs/adr/0003-trash-first.md.

**Interfaces:** Domain history records and CleanupJournal. InMemoryJournal fulfills HistoryRepository for now; plan 07 replaces persistence in composition. bytesMovedToTrash is a sum of successful logical sizes only; observedFreeSpaceDelta is optional signed observation.

- [ ] Write journal tests:
```swift
func testJournalFailureBeforeRemovalHasNoSideEffect() async throws {
    let harness = try await CleanupHarness()
    let candidate = try await harness.candidate(file: "project/node_modules",
                                               rule: "node.modules", risk: .low)
    await harness.journal.failNextBegin()
    let selection = await harness.selection(for: [candidate.id],
                                            irreversible: false, highRisk: false)
    let plan = try await harness.validate(selection)
    _ = await harness.execute(plan)
    let calls = await harness.trash.calls()
    XCTAssertTrue(calls.isEmpty)
}
```
Add failNextBegin and failNextRecord injection methods to InMemoryJournal. Test record failure after first success halts second item and preserves the first UI outcome as unrecorded; repeat must not re-execute. Test 4096 logical bytes moved does not become 4096 freed and free-space delta may be negative.
- [ ] Run JournalTests red. Implement write-ahead pending rows before any side effects and persist each outcome after it. Recovery marks pending rows indeterminate. Define a safe diagnostic export containing rule IDs/counts/error codes/version only; no original path, Trash URL, Docker resource name or stdout.
```swift
let summary = CleanupSummary(sessionID: plan.id, records: records,
                            bytesMovedToTrash: movedBytes,
                            observedFreeSpaceDelta: observedDelta)
```
Do not clamp negative observed delta to zero or call it causally reclaimed space.

## Exit gate

Forged/stale selections fail; no production rm/removeItem cleanup fallback; expired/reused plans cannot execute; known identity swaps blocked; errors/cancellation/journal failure tested; synthetic targets only.
