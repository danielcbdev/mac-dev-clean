# Cleanup rules

Every rule states what it detects, the evidence it requires, its risk level and
what the user loses. Nothing here is detected by directory name alone.

Filesystem items are moved to the **Trash**. Moving to the Trash does not free
space — space comes back when the Trash is emptied in Finder, which this app
never does for you.

## Project artifacts

Found only inside configured project roots, and only with evidence.

| Rule | Detects | Required evidence | Risk | Consequence |
|---|---|---|---:|---|
| `node.modules` | `node_modules` | A `package.json` in the same directory that parses as a JSON object | Low | Dependencies must be reinstalled. Local edits made *inside* installed packages are lost — they are not part of the project tree. |
| `node.turbo` | `.turbo` | A `package.json` **and** a `turbo.json`, both parsing as JSON objects | Low | Turborepo rebuilds without its local cache; the next build is slower. |
| `web.dist` | `dist` | A `tsconfig.json` whose `compilerOptions.outDir` is `dist`, **and** Git ignores `dist`, **and** Git tracks nothing inside it | Medium | The built site is gone until it is rebuilt. If it was being served or deployed from here, redeploy. |
| `flutter.build` | `build` | A `pubspec.yaml` showing Flutter | Low | The next build is a full rebuild. |
| `flutter.dartTool` | `.dart_tool` | A `pubspec.yaml` showing Flutter | Low | Package resolution and build metadata are regenerated. |
| `flutter.plugins` | `.flutter-plugins` file | A `pubspec.yaml` showing Flutter | Low | Regenerated by the next `pub get`. |
| `flutter.pluginDependencies` | `.flutter-plugins-dependencies` file | A `pubspec.yaml` showing Flutter | Low | Regenerated by the next `pub get`. |

### Why `build` is Flutter-only

`build` is an ordinary English word. Plenty of projects keep authored content in
a directory with that name. It is offered only when a `pubspec.yaml` in the same
directory shows Flutter, where the name has a defined meaning.

### Why `dist` needs three independent facts

A committed `dist` is common — many sites are deployed straight from the
repository. Detection therefore requires a static configuration declaring it as
output, Git ignoring it, **and** Git tracking nothing inside it. Any one of those
missing means no candidate, and if Git cannot answer at all, the directory is
skipped and reported for manual review.

A `tsconfig.json` containing comments does not parse as strict JSON, so such a
project's `dist` is skipped. That is deliberate: stripping comments correctly
requires a parser that must also get strings containing `//` right, and being
wrong there deletes work.

## Global caches

Exact, home-relative locations. Nothing is discovered by pattern, and no tool is
ever run to ask where its cache lives.

| Rule | Location(s), relative to home | Risk | Consequence |
|---|---|---:|---|
| `dart.hosted` | `.pub-cache/hosted` | Low | Packages are downloaded again. |
| `npm.cache` | `.npm/_cacache` | Low | Packages are downloaded again. |
| `yarn.cache` | `.cache/yarn`, `Library/Caches/Yarn` | Low | Packages are downloaded again. |
| `pnpm.store` | `Library/pnpm/store`, `Library/Caches/pnpm` | Low | Packages are downloaded again. Projects linked to the store reinstall. |
| `bun.cache` | `.bun/install/cache` | Low | Packages are downloaded again. |
| `gradle.cache` | `.gradle/caches` | Low | The next build is slower. |
| `pip.cache` | `Library/Caches/pip`, `.cache/pip` | Low | Packages are downloaded again. |
| `cargo.registry` | `.cargo/registry` | Low | Crates are downloaded again. |
| `cargo.git` | `.cargo/git` | Low | Git dependencies are cloned again. |
| `brew.cache` | `Library/Caches/Homebrew` | Low | Formula downloads are fetched again. |
| `pods.cache` | `Library/Caches/CocoaPods` | Low | Pods are downloaded again. |
| `xcode.derived` | `Library/Developer/Xcode/DerivedData` | Low | Full rebuild and re-indexing; the next build is noticeably slower. |
| `xcode.archives` | `Library/Developer/Xcode/Archives` | **High** | Archived builds and their symbol bundles are gone. Nothing regenerates them, and crash reports from a shipped build may become unsymbolicatable. |
| `xcode.devices` | `Library/Developer/Xcode/iOS DeviceSupport` | Medium | Symbols are re-downloaded and reprocessed the next time a device is attached. |
| `simulator.cache` | `Library/Developer/CoreSimulator/Caches` | Low | Simulator caches are rebuilt. |

### Deliberately excluded

These are **not** cleanup locations, and their absence is a decision rather than
an oversight:

- `~/.gradle` as a whole — it holds wrapper distributions and user settings, not
  only caches. Only `~/.gradle/caches` is offered.
- `~/.cargo/bin` and other installed binaries — removing them uninstalls tools.
- Homebrew's Cellar — that is the installation, not the download cache.
- `CoreSimulator/Devices` — simulator device data is user state, including
  installed apps and their databases.
- SDKs, Android emulator images and toolchains — expensive to replace, and not
  caches.

Custom cache locations require an explicit choice in Settings. MacDevClean never
runs a login shell or a tool to discover a location.

## Large Files

`manual.largeFile` is not a catalog rule. Nothing detects it. It applies only to
a file inside a folder the user explicitly chose for Large Files analysis, it is
classed **high** risk, nothing is ever preselected, and symbolic links are shown
as links without an action.

## Docker

Docker resources are covered separately in the Docker integration: they are
removed by reviewed identifier, the operation is irreversible, and it is labelled
as such. Stopped containers are **high** risk, because a writable layer can hold
data that exists nowhere else.
